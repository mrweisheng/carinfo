> v3 修订依据：第二轮审核（排除表 set→prefix、unclassified_count 算法、TYPE R 语义
> 三选一等）——关键指控已逐条实测复核，全部属实，其中 CROSS 排除名单实测比审核
> 指出的还要多漏 22 台（JAZZ CROSSTAR 21 + CROSSFIRE 1）。修订记录见附录 A。

## 一、背景：为什么现在没有车身类型

1. **源站 28car 不按车身分类**。它的分类只有用途五类（`car28.py:289-293` 的
   `h_f_ty=1..5`：私家车/客货车/货车/电单车/经典车），库里 `car_category` 就是
   这五个值（实测 21,633/424/399/454/537），没有 SUV/MPV 维度可抄。
2. **卖家描述里几乎不写车身词**（实测）：`7座+七座` 合计 4.4%、`跑車` 1.1%、
   `SUV` 1.0%、`開篷+敞篷` 0.5%、`房車` 0.2%、`MPV` 0.12%。靠描述提取车身不可行。
3. **现有 `extra_fields.body_type` 不可信**：`car28.py:1071` 是「描述里出现过该词
   就命中」且后命中覆盖前命中，实测 NOAH→跑車；全库仅 458 台有值。本方案**废弃**
   该字段，不迁移。
4. **车源结构极度集中在头部**（可行性根基）：base_model 共 1,293 个，
   top 80 车系覆盖 62.3%、top 150 覆盖 75.6%、top 189 覆盖 80.1%；
   ALPHARD 一个车系占 9.3%，前 24% 车源全是无歧义的日系 MPV。
5. **car_model（完整车型串）自带车身词**（消歧关键，实测）：
   COROLLA 209 台中 TOURING/SPORT/AXIO/CROSS 变体占 ~90%；MINI 的
   COUNTRYMAN(89)/CONVERTIBLE/CLUBMAN(31) 全部可分；A3 的 SPORTBACK/SEDAN 可分；
   脏键 RANGE（87 台）全是 Range Rover 系、GR（94 台）基本全是 GR YARIS/GR Corolla。
6. **本产品只做私家车**（用户已定）：检索默认 `vehicle_type=1`（spec.py:125）。
   私家車类目下厢式车合计仅 28 台（HIACE 16/NV200 5/VITO 3/TRANSPORTER 3/NVAN 1，
   base_model 口径）。这直接决定了 VAN 码的去留（见 §三）。

## 二、需求（用户原话归纳）

1. 按香港人常规习惯给车源划分车身类型。
2. 兼顾大陆叫法：大陆用户说「轿车」，香港叫「房車」——两边的话都要能搜；
   「SUV / MPV」两地叫法一致，直接通吃。
3. 接入智能搜索：「15 万左右的 SUV」「20 万左右的房车/轿车」都要灵活匹配
   （价格 near 是软偏好、body_type 是硬过滤，两者语义不同，explain 要能分开讲——
   见 §5.5）。
4. 车源全是香港的，标签口径以香港为准；**只服务私家车类目**。

## 三、分类体系（定稿：7 码 + 留白）

内部存**英文码**，展示层出双语标签。香港与大陆叫法都归一到同一个码——
「轿车」和「房車/房车」都落 SEDAN，需求 2 就此解决。

| 内部码 | 香港标签 | 大陆叫法（解析层全部收作同义词） | 库内规模感 |
|---|---|---|---|
| SEDAN | 房車 | 轿车、三厢、（简体）房车 | CAMRY、C200/E200、MODEL 3、S500 |
| HATCHBACK | 掀背（揭背） | 两厢、掀背、揭背 | JAZZ、FIT、SOLIO、GR YARIS、A3 SPORTBACK |
| WAGON | 旅行車 | 旅行车、旅行版 | COROLLA TOURING、CLUBMAN、AVANT |
| SUV | SUV / 越野車 | SUV、越野车 | MACAN、X5、RAV4、CAYENNE、DEFENDER |
| MPV | 七人車 | MPV、商务车、保姆车 | ALPHARD、VELLFIRE、STEPWGN、SERENA、ODYSSEY |
| CONVERTIBLE | 開篷車 | 敞篷车、cabrio | MX5、MINI CABRIO(25) |
| COUPE | **跑車** | 跑车、轿跑、轿跑车 | 911、TYPE R(273)、WRX(97)、GRAN COUPE(68)、CLA、PANAMERA |
| （空） | 未分类 | —— | 判不了的留白，前端显示「其他」，不做默认排除 |

**COUPE 码的语义定稿（v3，三选一取路线 1）**：COUPE = **跑車/轿跑大口袋**
（性能取向 + 双门轿跑），香港标签「跑車」。理由：
- 用户搜「跑車」时心里想的就是 TYPE R / 911 / WRX 这类——它们必须在同一个
  搜索结果里出现。TYPE R 实测 273 台（CIVIC 111 + FL5 53 + FK8 40 + FD2 20 +
  FN2 15 + INTEGRA 15 + FK2 12 + EP3 2 + 斯巴鲁系 4 + 杂 1），全是性能取向；
- v2 的「轎跑」标签与「TYPE R 归 COUPE」打架（CIVIC TYPE R 是五门掀背，
  标「轎跑」懂车的人一眼看出错）；标签回「跑車」后自洽——420IA/TT 这类
  双门轿跑出现在跑車结果里也不违和；
- 「轎跑」作为**大陆**同义词照收（解析层），只是不作香港主标签。

**VAN 撤销（v2 定稿，口径已修正）**：HIACE 按类目实测拆分为
**客貨車 169 / 私家車 16 / 貨車 5 / 經典 1**（base_model 口径，合计 191；
v1 写的 191 全口径当私家车是错的）。默认检索口径（vehicle_type=1）下厢式车
仅 28 台，不值得单列码；且「客貨車」已被 `MODEL_ALIASES` 注册为 HIACE 车系
别名（normalize.py:271），body 词表再收它就打架。处置：
- HIACE 的 16 台私家车在 R3 字典单独标 MPV；
- body 词表**不收**「客貨車/VAN/van仔」——「客货车」继续走既有车系别名→HIACE，
  行为与现状完全一致，不在本方案 scope 内动它；
- **已知且接受的行为**：撤销 VAN 后搜「客貨車」仍只返回 16 台私家车牌 HIACE
  （169 台客货车类目被 vehicle_type=1 默认挡住，历来如此）——上线后若有人
  报「搜客货车只有 16 台」，这是预期，不是 bug。

**「房车」（简体）照收 → SEDAN**：本产品用户群是「在搜香港二手车的人」，
会说「房车」又打简体的，正是知道香港叫法的大陆用户（需求原话场景）；
库里 RV/露营车为 0 台（实测 car_model 含 RV 露营类词 0 台），误伤面为零。

## 四、数据层：怎么判（确定性规则，零 LLM）

**原则：宁可漏判，不可误判**。字典全部人工确认，不用 LLM 批量猜。

判定在 `search/features.py` 重算管线内完成（`build_features`，features.py:463），
每次整表重算全量重判——同输入同输出，幂等、可回归、可版本化。

**各层真实分工**：R1 泛用词全库实测只命中 **1,316 台（5.6%）**——价值不在
覆盖，而在**变体分流**（S500 车系 102 台里有 9 台 `S500 COUPE AMG`，R1 先手
拦下，R3 才敢给 S500 整体标 SEDAN）。**覆盖主力是 R3 字典**（top 150 ≈ 75.6%
车源），其中约 150 条人工标注占整个方案 90% 的工作量——见 §七 第 0 步辅助脚本。

### 判定顺序（先到先得，上层命中不往下走）

- 歧义车系（MINI/COROLLA/CIVIC/GOLF/A3/BMW 3 系 5 系/奔驰 C 级 E 级 S 级）

  共 4,094 台，是留白主要来源）。
- 脏键家族级标注：RANGE→SUV、GR→HATCHBACK（SUPRA 由 R2 排除）、911→COUPE；

- HIACE→MPV（仅 16 台私家车，见 §三）。
- 查询顺序：先 `(brand, base)` 精确命中；brand 缺失时只在该 base_model
  字典全局同码时放行，防跨品牌撞键。
- **第一期规模：top 150 车系（75.6% 车源）**（用户已拍板，不加码 250）。

**R4 留白**：未命中 → `body_type = NULL`。**不做 seats>=7 推 MPV 兜底**
（seats 以 7 开头共 7,085 台，其中 7 座 SUV 约 **490** 台——DISCOVERY 122/X5 97/
LAND CRUISER 93/Q7 69/SORENTO 47/MODEL X 33/X7 29 等；seats 是座位数不是车身，
噪声大于信号）。

### 落表（vehicle_features 加 2 列）

```sql
body_type   varchar(12),            -- 7 码之一或 NULL（未分类）
body_source varchar(8),             -- 'rule'=R1/R2；'series'=R3；NULL=未分类
```

改动点（均在现有管线上，无新进程）：
- `features.py:87` CREATE_SQL 加两列。
- **⚠️ 新索引必须同时加进 `_shadow_ddl` 的 `index_map` 硬编码白名单
  （features.py:580-587）**：影子 DDL 索引名映射是写死的 dict，`idx_vf_body_type`
  不进 map 的话——第 1 轮重算索引建成、第 2 轮 `CREATE INDEX IF NOT EXISTS`
  发现**正式表**上同名索引已存在而跳过、swap 时正式表连同索引被 DROP——
  索引从此静默消失，无任何告警。
- **索引价值的准确说法**（v3 修正）：7 值低基数列，MPV(≈31%)/SUV(≈13%) 两个
  大头 planner 大概率不用这个索引，它只对 COUPE/CONVERTIBLE/WAGON 小码查询
  有意义。§六 的索引断言**防的是影子表机制的回归**（索引静默消失），
  **不代表性能收益**。真要索引收益需 `(body_type, price_ratio)` 复合索引——
  结论留第一期 EXPLAIN 实测后再定，本期不建。
- `RawRow` 加 `car_model` 字段（load_rows 的 SELECT 已取 car_model，现只喂
  normalize 后丢弃，features.py:225/249）。
- `build_features` 每行调 `body_types.classify(car_model, base_model, brand)`。
- 触发：无需新接线——`service.py:887` 每轮爬完已调 `rebuild_default()`。

## 五、检索层：怎么搜

### 5.1 SearchSpec（spec.py）

- 加 `body_type: str | None = None`。`__post_init__` 两件事：
  1. 白名单收敛：大写化后只认 7 码，脏值置 None；
  2. **把 `body_type` 加进 spec.py:216 的字符串字段收敛循环**——否则程序化
     调用方传 `{"body_type": 5}` 时 int 绑进 varchar 列比较，PostgreSQL 抛
     `operator does not exist` → 500。
- 单值不做多值列表：要「SUV 或跑車」就拆两组 queries（parser 本来按组输出）。

### 5.2 引擎（engine.py）

- `_where_clause`（engine.py:363，与 dealer 过滤 :460 同位置同模式）：

  ```python
  if spec.body_type:
      clauses.append(" AND f.body_type = %s")
      params.append(spec.body_type)
  ```

  探针（`_exists_sql`/`_count_sql`）复用同一 `_where_clause`，口径自动一致。
- `_SELECT`（engine.py:316）加 `f.body_type`；`ScoredVehicle` 加 `body_type` +
  `body_type_label`（香港标签：七人車/房車/跑車…），`to_dict` 一并输出。
- **硬过滤，不参与打分**；零命中放宽协议（`search_with_fallback`，
  engine.py:1108）**不放宽 body_type**——放宽成「任何类型」等于答非所问。

### 5.3 未分类漏检提示（v3 修正算法）

留白车会造成「部分命中的静默漏检」：搜「15 万左右的 SUV」命中 200 台时，
用户不知道还有一批 SUV 因未分类没进来——比零命中更危险。处置：

- 只要 `spec.body_type` 生效，结果就附带 `body_type_unclassified_count`。
- **算法（v3 修正）**：保留 spec 的**全部其他条件**，把 body_type 那一句换成
  `f.body_type IS NULL`——即 `_where_clause(replace(spec, body_type=None))` 的
  结果再手动拼上 ` AND f.body_type IS NULL` 做一次 COUNT。
  ⚠️ **不能**「去掉 body_type 条件直接 COUNT」（v2 的错误写法）：那数出来的
  是**所有类型**的车（搜 SUV 会得到「另有 12,000+ 台未分类」的荒谬提示），
  正确写法数的是**同条件下 body_type 为空**的车。
- 语义上这个数是「同条件未分类车数的上界」（未分类车里哪些真是 SUV 无从知道），
  文案就用：「另有 N 台车辆尚未分类，未能计入」。
- 实测成本：裸 COUNT 48-109ms，可接受。

### 5.4 解析层（parser.py）

**「七人車/七座」拆分（已拍板）**：

| 用户说 | 落地 |
|---|---|
| 七人車 / 七人车 | `body_type=MPV`（香港语义里「七人車」是**车型类别**） |
| 七座 / 7座 / N座 | `seats=N`（**座位数**，与车身无关） |

- **prompt 是软约束，必须有代码兜底**（09-24 P0 规矩）：`_group_to_spec`
  （parser.py:420，签名里有 query 原文）加一条——原文含「七人車/七人车」
  且解析出 `body_type=MPV` 时，**丢掉 seats**（模型完全可能同时给
  `{"body_type":"MPV","seats":7}`，字面「七人」就是 7）。
- 现状 parser.py:81（prompt「七人车/七座→7」）与 :884（规则路径 seats 正则的
  `N人車` 分支）同步拆开。
- 为什么值得改：现状把「七人車」当座位数，seats=7 共 7,085 台里含约 490 台
  7 座 SUV——搜「七人車」返回一堆越野车，正是本次要修的错。

**LLM 主路径**：
- `ALLOWED_LLM_FIELDS`（parser.py:41）加 `body_type`；
  `LLM_KEY_ALIASES`（parser.py:146）加 `body/car_type/vehicle_body → body_type`。
- `SYSTEM_PROMPT`（parser.py:53）字段清单加：

  ```
  body_type       车身类型，枚举：SEDAN(房車/轿车) HATCHBACK(掀背/两厢) WAGON(旅行車)
                  SUV(越野车) MPV(七人車/商务车) CONVERTIBLE(開篷/敞篷) COUPE(跑車/轿跑)
                  ⚠️「七人車」是车型类别 → body_type=MPV；「七座」才是座位数 → seats=7
  示例："15万左右的SUV"    → {"price_near": 150000, "body_type": "SUV"}
        "20万左右的房车"   → {"price_near": 200000, "body_type": "SEDAN"}
        "找台七人车"       → {"body_type": "MPV"}
        "七座的SUV"        → {"body_type": "SUV", "seats": 7}
  ```

**规则兜底路径**（`rule_based_parse`，parser.py:739），在车型/品牌识别之后加
类目词扫描（长词优先）：
- `越野車|越野车|SUV|吉普` → SUV
- `七人車|七人车|MPV|保姆车|保姆車|商务车|商務車` → MPV（与座位数正则分开，
  现有 seats 正则 parser.py:884 的 `N人車` 分支删掉，避免双写）
- `房車|房车|轿车|轎車` → SEDAN
- `掀背|揭背|两厢|兩廂` → HATCHBACK（展示层用「掀背（揭背）」，不用异体「掲背」）
- `旅行車|旅行车|旅行版` → WAGON
- `開篷|开篷|开蓬|開蓬|敞篷` → CONVERTIBLE
- `跑車|跑车|轿跑|轎跑` → COUPE
- **不收** `客貨車/van仔`（§三：与既有车系别名打架，且非私家车业务）
- 冲突核对：`越野路華`（LAND ROVER 品牌别名）比 `越野` 长，品牌段先命中，
  body 段再命中 SUV——双条件都真，语义无损；「七人車」在
  `_ALIAS_BLACKLIST`（aliases.py:103）挡着不会当车系别名，无劫持。

### 5.5 explain（v2 补，v3 保留）

- `explain.summarize()` 的 target 摘要带上 body_type（该函数现在连 `family`
  都缺，一并补，「特斯拉 Model 3」不再显示成光秃秃的 TESLA）。
- price_near（软）与 body_type（硬）分开口径：零命中时诊断文案要能区分
  「这个类型没车」和「有车但价格都不在你说的范围」——用去掉 body_type /
  去掉价格条件的 EXISTS 探针分别探一次（探针机制现成，engine.py:505/515）。

- `/search/spec`（api.py:418 `SearchSpec.from_dict`）自动获得 `body_type`
  入参与返回（from_dict 走 dataclass 全字段白名单，spec.py:313，无需改动）。
- **MCP `search_by_spec`（mcp_server.py:346）必须改两处**（v3 补，FastMCP 从

  1. 函数签名加 `body_type: str | None = None`；
  2. description 补一段枚举说明（7 码 + 双语叫法 + 「七人車→MPV、七座→seats」）。
