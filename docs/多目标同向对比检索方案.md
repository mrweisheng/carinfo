# 多目标同向对比检索方案（"奔驰SUV或者宝马都可以"）

> 状态：待拍板（2026-10-01）。现状行为为当日本库实测；行业参照来自公开调研
> （AutoTrader/Cars.com 筛选器模式 + 搜索多样性文献 MMR/intent-aware 配额）。

## 一、需求

销售/代购向客户介绍车时的常见话术：

1. **同向多品牌**：「帮我找几台 15 万左右的奔驰 SUV 或者宝马的都可以」
2. **同向多车系**：「帮我找几台 18 万左右的阿尔法、威尔法都可以」
3. **精确车缺货降级**：「帮我找一台奔驰 GLC 200」→ 没有 → 推荐「奔驰的 SUV」

两个核心问题：①怎么设计；②多品牌/多条件时，有限返回条数怎么排序、每个条件给几台。

## 二、现状实测（2026-10-01，LLM 主路径）

| 查询 | 现状解析 | 现状检索行为 | 差距 |
|---|---|---|---|
| 奔驰 SUV 或者宝马都可以 | 拆 **2 组**（brand=MERCEDES-BENZ / BMW，各带 body_type=SUV、price_near） | 每组独立检索各取 5 台，**组内拼接**（奔驰 5 台在前、宝马 5 台在后），总条数=组数×limit | 无交错；总量翻倍；无全局配额 |
| 阿尔法、威尔法都可以 | 拆 2 组（各一个 base_model） | 同上 | **引擎其实已支持 `base_models = ANY` 合并池**（spec.base_models），解析层没用上——白捡的能力 |
| 奔驰 GLC 200 | **实测不稳定（2026-10-01 两次解析走了两条错路）**：①解析成 `base_model='200'`——该键实为丰田 200（2 台），品牌过滤后 0 台；②解析成 `model_keyword='GLC 200'`→模糊 0 命中→**整个关键词被零命中协议丢弃**，退化为「全部奔驰按分混排」（EQA250/A200/W123 都进了前 5，与 GLC 无关） | 两条路径都到不了用户要的行为（「GLC 没有 → 推荐 GLC 兄弟车/奔驰 SUV」）；根因=库里只有 GLC250/300/43/63S 分键、没有 GLC200，解析层没有「家族前缀拆解 + 兄弟车兜底」 |

多组解析协议本身是好的（prompt 已教「阿尔法或者威尔法」拆组），**缺的是：同向合并 + 组间配额策略**。

## 三、行业参照

1. **产品模式**：AutoTrader / Cars.com / CarGurus 的筛选面板都是 Make/Model **多选 checkbox → 合并进单一结果列表**（OR within dimension, single pool）；Carousell 历史上只许单选分类，用户被迫多次搜索——是反例。**结论：同向条件合并单池是行业标准做法**。
2. **多样性与配额**（搜索多样性是成熟领域）：
   - **MMR**（Carbonell & Goldstein 1998）：贪心选「相关性 − λ×与已选相似度」，防重复霸屏；
   - **Intent-aware 配额轮转**（Dang & Croft；xQuAD/PM-2）：按意图/类目分配名额、轮转交错，防单类目独占。
   - 电商（eBay/Amazon 研究线）同样以类目多样性为标配。
   
   来源：[Demand-Calibrated Facet Diversification](https://www.researchgate.net)、[LDA-based Diversified Retrieval for E-commerce (ACM)](https://dl.acm.org)、[Intent-Aware Search Result Diversification](https://www.academia.edu)。

## 四、方案设计

### 4.1 关键判断：多目标分两类，走两条路径

| 类型 | 特征 | 例子 | 路径 |
|---|---|---|---|
| **同向多目标** | 各条件完全相同，只有品牌/车系不同（「或者/都可以/也行」） | 奔驰SUV 或 宝马SUV；阿尔法 或 威尔法 | **合并单池**（一次检索、一个排名、全局 limit） |
| **异向多目标** | 各组条件有实质差异（年份/价格/车型都不同） | 14年威尔法，再找台14年埃尔法 | 保持多组独立检索 + **交错合并**（§4.3） |

**为什么同向要合并而不是拆组**：①排名池统一，跨品牌分数可比（同锚点同权重），"宝马 X3 0.92 分、GLC 0.90 分"自然交错，销售看到的是"这 5 台最值的"，不是"奔驰前 5 + 宝马前 5"；②全局 limit 天然生效，配额问题消解大半；③与行业标准一致。

### 4.2 同向合并的实现（数据结构已有一半）

**spec 加 `brands: list[str]`**——完全镜像既有 `base_models` 的模式（白名单收敛、防呆、`base_model` 代表键回填）：

```python
# spec.py（照抄 base_models 的收敛模式）
brands: list[str] = field(default_factory=list)
# engine._where_clause
if spec.brands:
    clauses.append(" AND f.brand_norm = ANY(%s)")
    params.append(list(spec.brands))
```

- 「阿尔法、威尔法都可以」→ 解析层合成为**一组** `{base_models:[ALPHARD,VELLFIRE], price_near}`——引擎**今天就支持**，只改解析层（prompt 教会「同向就合组输出」+ resolve 层累积多车系）。
- 「奔驰SUV或者宝马」→ 一组 `{brands:[MERCEDES-BENZ,BMW], body_type:SUV, price_near}`。
- 判「同向」的兜底规则：解析层拿到多组后，若**除 brand/base_model/family 外全部字段相等** → 合并成一组（brands 取并集 / base_models 取并集）。LLM 已合组就不重复处理。
- 变体展开、别名解析照常在组内生效（VELLFIRE→[VELLFIRE,VELLFIREH]）。

### 4.3 组间排序与配额（问题 2 的正面回答）

**异向多组**（保持多组时）改合并策略——现状是拼接，改为 **交错轮转 + 全局配额**：

```
各组先按分排好 → 第 1 轮:每队出 1 台(按组分顺序) → 第 2 轮:每队再出 1 台 → …
→ 攒够全局 limit(默认 5)停 → vehicle_id 去重(保留高分/先到组)
→ 某组候选耗尽,名额顺延给其他组
```

- **为什么轮转而不是全局分数大排序**：各组锚点不同时（威尔法要 14 年、埃尔法要 18 年），near 分数跨组不可比；轮转只在**组内**比分数，天然规避。
- **为什么不硬性"每组 N 台"**：组会耗尽（奔驰只有 2 台个人车源），硬配额会出现"宝马 3 台+奔驰凑不够"的尴尬；顺延机制自然处理。
- **每条带组标签**（现状 query_groups 已有），前端可按组过滤/标色——配额的最终弹性交给展示层。

**同向合并池内**（brands/base_models）的多样性：

- 全局 limit 下按分数取 top——配额由排名自然产生（3 奔驰 + 2 宝马这类）；
- **可选：同车系上限 M**（如 M=2：同 base_model 最多出 2 台，第 3 台起让位给下一个车系）。这防的是"5 台几乎一样的 ALPHARD"——**单品牌查询同样受益**。依据即 MMR 的去冗余思想，实现极简（计数器贪心，不引向量/相似度）。默认开还是关 → 拍板项 3。
- 汇总口径：summary 报「按『奔驰 SUV 或宝马 · 15 万左右』找到 N 台（奔驰 x / 宝马 y）」，total_matched 仍报全池。

### 4.4 零命中与降级

- **brands 池**：全 0 时**按品牌分别探针** → fb_notes 出「宝马在该条件下 0 台，奔驰还有 N 台」（对销售场景极有用：当场换话术）。全部品牌都 0 才走通用放宽阶梯。
- **多组**：每组已有独立零命中协议（现状保留）；交错合并时空组不占名额，其 fb_notes 照常透出。
- **都不放宽 body_type**（车身是硬条件，原则与单目标一致，留白提示已有 unclassified_count）。

### 4.5 精确车缺货降级（用户场景 3，与车身类型天然联动）

「奔驰 GLC 200」没有 → 推荐奔驰 SUV。两步：

1. **解析修正**（小）：关键词含已知车系前缀时走 family（'GLC 200' → brand+family='GLC'，引擎前缀正则命中 GLC250/GLC300…）。修复现状误落 '200' 键的问题。
2. **缺货降级**（零命中协议加一级）：family/车系零命中时，若该家族车辆在字典中的 body_type 唯一 → 降级建议 **brand + body_type**（GLC 系全是 SUV → 「没有 GLC 200，同价位奔驰 SUV 还有 N 台」）。这正是车身类型字段刚建好的第一个高阶用途；LM350→MPV、MACAN→SUV 同理。
3. 降级必须**显式告知**（fb_notes），不静默扩大。

## 五、拍板项

1. **同向合并单池**（§4.2）——推荐做，这是本方案的核心收益。
2. **异向多组从拼接改为交错轮转+全局配额**（§4.3）——推荐做；注意这会改变现有多目标查询的返回结构（总条数从 组数×5 变为全局 5），需确认前端/调用方可接受。
3. **同车系上限 M**（推荐 M=2，且**全场景生效**——单品牌查询同样防雷同；要保守就先只在多目标场景开）。
4. **GLC 200 缺货降级**（§4.5）——推荐纳入本次（用户场景 3 + 车身类型联动收益高）；解析修正（family 前缀）无论如何都该修。
5. 「几台/几架」要不要映射 limit（现在固定默认 5）——建议本期不做，保持 limit 语义单一。
